# Data Model: Measurable Jev Skill Assistance

## Model boundaries

The authoritative active-session model is a validated event stream stored as Pi custom entries on
the active session branch. Aggregate counters are derived views, not writable state. Candidate bodies,
logs, prompts, credentials, personal data, and Jev raw responses are outside this telemetry model.

## Enumerations

### Approved skill ID

Exactly these values are accepted:

- `scientific-method-debugging`
- `receiving-code-review`
- `coordinate-implementation`
- `track-open-issue`
- `speckit-analyze`
- `speckit-checklist`
- `speckit-clarify`
- `speckit-tasks`

`finish-session` may request retrieval or closeout but is not a Jev proposal-producing skill ID.

### Invocation terminal status

- `succeeded`: Jev returned one valid score answer for every candidate.
- `unavailable`: executable, authentication, provider, or tracking prerequisite was unavailable.
- `failed`: Jev returned a nonzero transport/provider/local execution failure.
- `malformed`: stdout parsed incorrectly or did not contain the expected answer set and value types.

Only `succeeded` contributes to successes and proposals. Every invocation start contributes one
attempt, regardless of terminal status.

### Disposition kind

- `accepted`: the main agent used this proposal's recommended position/group in its decision.
- `overridden`: the main agent deliberately chose a conflicting position/group after review.
- `not_used`: the proposal was reviewed but did not participate in the final decision.

No event represents pending. `pending` is derived from proposals without a valid disposition.

## Entities

### InvocationStart

A durable statement that the instrumented interface began one Jev attempt.

| Field | Type | Rules |
| --- | --- | --- |
| `schemaVersion` | literal `1` | Required |
| `eventType` | literal `invocation_started` | Required |
| `eventId` | UUID | Unique within session branch |
| `invocationId` | UUID | Unique within session branch |
| `sessionId` | non-empty string | Must equal current Pi session ID |
| `skillId` | Approved skill ID | Required |
| `startedAt` | ISO-8601 UTC string | Generated by extension clock |
| `candidateIds` | array of opaque IDs | 2–50 entries, unique, input order preserved |

Candidate IDs use `^[A-Za-z0-9][A-Za-z0-9._:-]{0,63}$`. They must be seam-owned opaque identifiers,
not candidate text or hashes of candidate text.

### InvocationTerminal

The one terminal result for an invocation.

| Field | Type | Rules |
| --- | --- | --- |
| `schemaVersion` | literal `1` | Required |
| `eventType` | literal `invocation_terminal` | Required |
| `eventId` | UUID | Unique within session branch |
| `invocationId` | UUID | Must reference one start event |
| `sessionId` | non-empty string | Must equal start and current session |
| `finishedAt` | ISO-8601 UTC string | Not earlier than `startedAt` |
| `status` | Invocation terminal status | Required |
| `failureClass` | enum or absent | Present only for non-success; no raw stderr |
| `proposals` | array of Proposal | Exactly one per candidate on success; empty otherwise |

Allowed `failureClass` values are `cli_missing`, `auth`, `input`, `provider`, `retryable`,
`cancelled`, and `response_schema`. Error text, stderr, endpoint, provider payload, model output, and
credentials are not stored.

### Proposal

One Jev-recommended score/rank for one candidate.

| Field | Type | Rules |
| --- | --- | --- |
| `proposalId` | string | `${invocationId}:proposal:${candidateId}` |
| `candidateId` | opaque ID | Must occur in referenced start event |
| `rank` | integer | 1 through candidate count; unique |
| `score` | finite number | Parsed score used for stable ordering |
| `confidence` | finite number or absent | Preserved only when normalized response supplies it |

The proposal contains no candidate body. Ties in score are ordered by the original candidate index.
A malformed or partial answer set creates no proposals and makes the invocation `malformed`.

### Disposition

The first valid terminal judgment by the main agent for one proposal.

| Field | Type | Rules |
| --- | --- | --- |
| `schemaVersion` | literal `1` | Required |
| `eventType` | literal `proposal_disposition` | Required |
| `eventId` | UUID | Unique within session branch |
| `proposalId` | string | Must reference a successful proposal on active branch |
| `sessionId` | non-empty string | Must match proposal/current session |
| `skillId` | Approved skill ID | Must match proposal's invocation |
| `disposition` | Disposition kind | Required |
| `recordedAt` | ISO-8601 UTC string | Generated by extension clock |

A replay of the same `proposalId` and disposition returns the existing result without appending an
event. A different disposition for an already-disposed proposal is invalid and cannot replace it.

### InvalidEvent

A privacy-safe diagnostic that prevents bad input from being mistaken for a valid zero.

| Field | Type | Rules |
| --- | --- | --- |
| `schemaVersion` | literal `1` | Required |
| `eventType` | literal `invalid_event` | Required |
| `eventId` | UUID | Unique |
| `sessionId` | non-empty string | Current Pi session |
| `operation` | `rank` or `disposition` or `closeout` | Required |
| `reason` | stable reason enum | No raw input or error text |
| `recordedAt` | ISO-8601 UTC string | Generated by extension clock |

Reason values include `duplicate_terminal`, `unknown_proposal`, `cross_session`,
`conflicting_disposition`, `schema_invalid`, `store_missing`, `store_unreadable`, and
`store_invalid`.

### MetricsSummary

A derived view for the total session and each approved skill represented in valid events.

| Field | Type | Invariant |
| --- | --- | --- |
| `sessionId` | string | Current Pi session |
| `leafId` | string or null | Current active branch leaf |
| `scope` | `session` or approved skill ID | Required |
| `attempts` | non-negative integer | Count of unique starts |
| `successes` | non-negative integer | Successful unique terminals |
| `proposals` | non-negative integer | Proposals from successful terminals |
| `accepted` | non-negative integer | Unique valid accepted dispositions |
| `overridden` | non-negative integer | Unique valid overridden dispositions |
| `notUsed` | non-negative integer | Unique valid not-used dispositions |
| `pending` | non-negative integer | `proposals - accepted - overridden - notUsed` |
| `invalidEvents` | non-negative integer | Validated invalid diagnostic entries |
| `coverage` | literal `instrumented-only` | Always shown |
| `storeState` | `available`, `missing`, `unreadable`, or `invalid` | History only |

For every summary:

- `successes <= attempts`
- `accepted + overridden + notUsed + pending = proposals`
- Counters never include a duplicate event, unknown proposal, cross-session proposal, abandoned
  branch, or uninstrumented shell/MCP call.

### CloseoutRow

The persistent cross-session snapshot appended once by `finish-session`.

| Column | Type | Rules |
| --- | --- | --- |
| `schema_version` | integer | `1` |
| `closed_at` | ISO-8601 UTC | Extension clock |
| `session_id` | string | Unique key within project-partitioned CSV |
| `leaf_id` | string | Active leaf at closeout; empty only if Pi reports no leaf |
| `skill_ids` | pipe-delimited approved IDs | Sorted; empty when no tracked attempt |
| `attempts` | integer | Session aggregate |
| `successes` | integer | Session aggregate |
| `proposals` | integer | Session aggregate |
| `accepted` | integer | Session aggregate |
| `overridden` | integer | Session aggregate |
| `not_used` | integer | Session aggregate |
| `pending` | integer | Session aggregate |
| `invalid_events` | integer | Session aggregate |
| `coverage` | string | `instrumented-only` |

Rows use RFC 4180 quoting and a fixed header. The file path is derived from a SHA-256 fingerprint of
the canonical project root, but neither the root nor its fingerprint is included in a row.

## Relationships

```text
Pi session (1)
  └── active branch (1)
      ├── InvocationStart (0..*)
      │    └── InvocationTerminal (0..1)
      │         └── Proposal (0..50; only on success)
      │              └── Disposition (0..1 valid)
      └── InvalidEvent (0..*)

Validated active-branch events -> MetricsSummary (session + per skill)
Session MetricsSummary -> CloseoutRow (0..1 per session ID)
```

## State transitions

### Invocation

```text
requested
  -> started
      -> succeeded
      -> unavailable
      -> failed
      -> malformed
```

No terminal state may transition again. A second terminal event is invalid and ignored by
aggregation.

### Proposal

```text
pending
  -> accepted
  -> overridden
  -> not_used
```

Each terminal disposition is final. Repeating the same transition is idempotent; attempting a
second, different terminal state is invalid.

### Closeout

```text
not_exported
  -> exported
  -> already_exported (idempotent replay; no new row)
  -> store_error (explicit failure; no success claim)
```

## Reconstruction and validation order

1. Read only custom entries from `getBranch()` with the owned custom type and supported schema
   version.
2. Validate structural fields without trusting stored values.
3. Deduplicate event IDs.
4. Index invocation starts; attach at most one valid terminal event to each.
5. Materialize proposals only from valid successful terminals.
6. Apply at most the first valid disposition per proposal.
7. Count invalid diagnostics separately and derive pending.
8. Produce total and per-skill summaries with denominators and coverage note.

Unsupported schema versions, corrupted entries, and inaccessible CSV history are reported explicitly;
they never produce a fabricated zero.
