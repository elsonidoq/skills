# Tasks: Measurable Jev Skill Assistance

**Input**: Approved design documents in `specs/001-jev-skill-metrics/`

**Prerequisites**: `plan.md`, `spec.md`, `research.md`, `data-model.md`, `quickstart.md`, and `contracts/`

**Tests**: Required by FR-014. Test tasks are fail-first, fixture-driven, deterministic, and must not call a live Jev provider or run a benchmark.

**Organization**: Tasks are grouped into contiguous user-story phases. Each task records its outcome, dependencies, likely files/interfaces, acceptance evidence, capability needs, model class, and rationale.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Safe to execute in parallel after its stated dependencies because it owns different files/interfaces.
- **[Story]**: User-story traceability label for story-phase tasks.
- **Model classes**: `sonnet-class` is the default; `opus-class` is reserved for tightly coupled invariant, lifecycle, or transactional work.

- **Phase 6 (Documentation/verification)**: T032 → T033 → T034 → T035 after all desired stories are complete.

### User Story Dependency Graph

```text
Setup T001/T002
  -> Foundation T003-T006
      -> US1 T007-T015 (trusted measured boundary and closeout)
          -> US2 T016-T021 (four guarded global seams)
              -> US3 T022-T031 (transactional activation and four SpecKit layers)
                  -> Docs/Acceptance T032-T035
```

- **US1 (P1)** is the MVP and has no dependency on another story after Foundation.
- **US2 (P2)** depends on US1 because every measured seam must use the working tracker and disposition path.
- **US3 (P3)** depends on US2 because installation activates only already verified seam resources; it still has its own independent temporary-install test.
- The sequential story dependency is intentional: it enforces the approved rule that no optimized seam is enabled before trustworthy tracking and no installer activates an unverified seam.

### Within-Story Ordering

- Fail-first fixture tasks precede their implementation tasks.
- Event/schema and aggregation precede process, CSV, and Pi adapters.
- The tracker precedes skill seam changes; seam resources precede activation.
- Preset manifest precedes command layers; all layers precede reconciliation/activation.
- Documentation follows tested behavior; complete validation follows documentation.

### Parallel Opportunities

- T001 and T002 own JavaScript and shell test helpers independently.
- T011 and T012 create separate adapter and privacy test files after process/CSV modules exist.
- T017–T020 and T026–T029 are intentionally sequential despite separate files, preserving the approved plan's shared-seam review constraint.
- No task marked `[P]` writes the same file as another concurrently eligible task.

## Implementation Strategy

### MVP First (US1)

1. Complete Setup and Foundation.
2. Complete T007–T015 in order, using fail-first fixtures.
3. Stop and validate exact counters, replay invariance, branch reconstruction, privacy sentinels, and one-row closeout.
4. Do not enable any optimized seam until this checkpoint passes.

### Incremental Delivery

1. **US1**: Deliver trusted instrumented metrics and closeout.
2. **US2**: Add and independently verify exactly four guarded global seams.
3. **US3**: Add transactional opt-in installation and exactly four project-local SpecKit append layers.
4. **Closeout**: Update established documentation owners and run the complete deterministic acceptance set.

### Scope Guardrails

- No live Jev provider call, A/B benchmark, token/latency/quality claim, deployment, or database migration.
- No raw shell/MCP Jev substitution for measured use.
- No direct edits to generated `.pi/prompts/speckit.*.md` files.
- No seam beyond the eight approved IDs; `compact-memory` remains excluded.
- No persisted candidate bodies, criteria, prompts, logs, raw Jev output, stderr, credentials, personal data, project paths, or provider endpoints.
- Main-agent responsibility remains unchanged for architecture, root cause, code generation, authorization, correctness, and final verification.
