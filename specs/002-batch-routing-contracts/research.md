## Decisions / alternatives

1. **Decision:** distill supplied CSV signals in this feature research and reusable seed instructions; do not add the 369-row external file as runtime input or store a second benchmark database. **Why:** compact portable fallback and selective provenance suffice. **Alternative:** copying raw dataset would be useful for later independent exploration but is not required to route and risks assuming every cross-harness row is comparable.
2. **Decision:** keep runnable task contract items in existing task acceptance fields, batch union in coordinator brief/tracker, and attempt feedback in existing coordination run/task records. **Why:** preserve established owners and current-content approvals. **Alternative:** YAML store/schema duplicates memory and acceptance contracts.
3. **Decision:** treat provider capability and selected profile as separate gates: family/effort are chosen independently with owner authorization and supported runtime binding; benchmark evidence is a qualified prior, not a hard eligibility rule. **Why:** observed row absence is not proof a pairing cannot execute. **Alternative:** benchmark-only eligibility would prevent otherwise supported profiles and contradict current approved batch spec.
4. **Decision:** retain one final independent review and per-task checkpoint audits, remove any mandatory *per-batch* strong review. **Why:** cheap path without weakening end-of-run assurance.
