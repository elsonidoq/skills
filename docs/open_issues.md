# Open Issues

## OI-1: Repository-memory reconcile has untested concurrency and platform paths

- **Status:** open
- **Problem:** The default-on `repositoryMemory` reconciliation mutates the filesystem: it creates the in-repo memory directory and replaces the central `~/.claude/projects/<key>/memory` path with a symlink to it (and removes a central dir only when it is atomically confirmed empty). Three boundary paths are reasoned safe in code review but remain unverified: (a) two plugin instances or processes reconciling the same canonical root concurrently (main repo plus a worktree, or two OpenCode processes); (b) the `MAX_NOTIFIED_SESSIONS` (500) FIFO eviction boundary for repository-memory notices; (c) symlink-unsupported platforms (e.g. Windows without developer mode), where only a `chmod`-induced failure is exercised, not a real no-symlink environment.
- **Primary evidence:** `opencode-claude-memory-v2-port/src/store/repositoryMemory.ts` (uses `rmdirSync` for atomic emptiness, `isDirectory(repoDir)` before linking, realpath containment) and `opencode-claude-memory-v2-port/src/index.ts` (bounded, fire-and-forget notice path). `opencode-claude-memory-v2-port/test/repositoryMemory.test.ts` covers sequential reconcile, foreign/dangling/symlink-to-file shapes, a read-only-parent failure, and location scoping, but contains no concurrent-reconcile test, no eviction-boundary test, and no real no-symlink run. The second independent review (round 2) recorded these as findings 3 and 6 and confirmed the other findings fixed.
- **Resumption condition:** Add a cross-process test that reconciles the same canonical root from two processes and asserts exactly one non-dangling link with no memory loss; add a test that drives the notice set past `MAX_NOTIFIED_SESSIONS` and asserts correct eviction; run the symlink tests in a no-symlink environment (or with `symlinkSync` forced to throw `EPERM`) and assert graceful fallback to the central path with a notice and no crash.
