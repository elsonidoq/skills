## Scope and approach

Use the existing package operational owners, not a new workflow layer. Planner's
correction boundary and approval/recovery contract must agree: a coordinating parent
may directly fix formatting, typos or broken links only after comparing the actual
before/after diff and establishing no change to requirements, decisions, scope,
dependencies, acceptance or approval validity. A cosmetic label alone is insufficient.
Record the equivalence comparison in the existing return/approval convention and
retain comparable current-content evidence; do not silently reuse a stale digest.
Uncertain or substantive changes return to a suitable originating producer or fresh
bounded correction delegate, affected review and approval renewal. Creation still
uses separate fresh bounded producers; an independent reviewer never becomes the
producer. Missing required delegation stops substantive work, not an inline fallback.
Authorized retained corrections still follow the shared task-commit contract.

Align all operative carriers: REQUIREMENTS, planner (including both path reviews),
approval/recovery, managed Standard helper, coordinator where its correction/intake
text needs alignment, initialize-coherence adoption/refresh wording and affected
focused checks/fixtures. Refer to package owners rather than copying mechanics into
adopted AGENTS sections. Keep project memory associations and documentation-owner maps
locally explicit. Necessary discovery/setup text may point to the contract without
becoming another operational rulebook; historical plans/approvals remain untouched.

For Cerca, replace duplicated operative mechanics inside and outside its marked
Coherence block with installed-package references. Preserve active product, security,
data/privacy, permissions (including standing bounded read-only access and prohibitions
on writes/live spending), branch/worktree restrictions, Jev, communication, custom
memory paths and documentation ownership. Remove mandatory STATE-first execution and
ledger/snapshot upkeep rules; preserve existing STATE/custom content and its documented
location, without initialization, migration or automatic maintenance. Keep the approved
83cabbd mechanical intent in force through the aligned package contract. Refresh old
adoption provenance with new content-bound authority; do not relabel old approval as
permission for the amendment or broader edits.
