## What and how

### Run identity: readable display without changing identity

Owner requirement, clarified by the explicit **Show existing identifier + folder** choice: show the retained **original run identifier + final worktree folder name**, e.g. `review-convergence-20261024 · curvy-skunk`; never a full worktree path. Some identifiers are meaningful; generated identifiers are also shown when they are all that exists. This display label is not a separately stored human name. No persisted naming system.

Observed evidence and derived constraints:

- [`public.py:minimize`](../../workflow_monitor/public.py) currently supplies constant `Recorded run` and raw `run_id` as `display_id`. [`app.py:_qualify_public`](../../workflow_monitor/app.py) prefixes that ID with the recording hash and adds `source`. Preserve these identity/routing operations and exact matching.
- [`cli.py:main`](../../runtime/coherence_workflow/cli.py) uses `--run` as the run ID or defaults to `uuid.uuid4().hex`. [`monitoring.py:_descriptor`](../../runtime/coherence_workflow/monitoring.py) and [`store.py:register_monitor_run`](../../runtime/coherence_workflow/store.py) retain no independent human run name. Use the original retained `run_id` directly as the display label, whether meaningful or generated, per the owner's answer. The smallest change is to populate the existing public `label` from that raw ID in `minimize`, before recording qualification. Do not parse a recording-qualified `display_id` or opaque ref to recover/invent a label, infer meaningfulness, or add a nullable run-name abstraction. Synthetic mockup names are not production data.
- [`projects.py:Recording` and `Projects.refresh`](../../workflow_monitor/projects.py) retain a live worktree `Path` internally. Expose only its `.name` as nullable display metadata, e.g. `worktree_name`, through run DTOs. For a live main/linked recording this means the registered worktree basename. [`recordings.py:PreservedBinding`](../../workflow_monitor/recordings.py) retains only opaque origin identity, while preserved `Recording.worktree` points to main storage. For preserved recordings display **Worktree name unavailable**, never that storage basename. A single-reader route without a verified live binding also uses the unavailable fallback, not a guessed path.

Use the existing `label` for the original run identifier and add only the nullable display-only worktree basename at the recording qualification seam, without widening arbitrary payload exposure. Apply these consistently to single-reader lists/snapshots and project-qualified lists/snapshots, including safe cached reads. Reuse existing safe text/type handling and inert text rendering; unsafe or missing display values use an honest unavailable fallback, not an invented naming policy. Missing worktree metadata uses the same unavailable text in the selector and heading. Neither label nor basename availability may alter opaque refs, qualified `display_id`, routing, snapshot references, ordering, polling or recorded acceptance.

The run selector and selected heading use the same compact display formatter. Keep readable start context and source as secondary text. Distinguish multiple runs without the current filtered-list index: a compact stable qualifier can use the existing qualified identity as a disambiguator, not as the principal name. Its derivation must be independent of filter/page position and other runs' presence; do not invent persisted names or parse arbitrary IDs into names. The implementation may choose the compact qualifier encoding as a routine technical detail, provided collision handling is deterministic and labels do not silently identify two runs as one. Filter displayed identifier/worktree/start/qualifier text locally; preserve existing run-ID substring matching as an additional search input and preserve no-match/selected-outside-filter behavior. Filtering never changes selection, history or routes.

**Observable result:** a live recording with raw `run_id` `review-convergence-20261024` shows `review-convergence-20261024 · curvy-skunk` in both rail and heading. A generated UUID identifier remains that identifier in the display label, not unavailable text. The list and snapshot `label` agree on the original identifier while qualified `display_id` and opaque refs remain unchanged for routes/API matching. A preserved recording still shows its retained identifier, with **Worktree name unavailable** for its unknown original source folder.

### Retained task title and detail fidelity

[`public.py:minimize`](../../workflow_monitor/public.py) already exposes it. [`graph.ts:taskTitle`](../../workflow_monitor/web/src/graph.ts) ignores it and maps generic/ID-only labels to `Recorded task`.

Use the existing helper, not a new summary system. Keep a meaningful retained label. For a blank/generic/ID-only label, use a faithful leading excerpt of nonblank retained `work_description`, with whitespace collapsed only for the short title. Reuse the helper's current 80-character short-title limit and ellipsis behavior; that existing display budget is not a new data limit. If neither supplies meaningful text, show **Description unavailable**. Do not strip a meaningful label merely because it starts with “Task”; a number/ID alone is not meaningful prose. Stable source-order Task N, role and correction/review ordinal remain distinguishable. Full original work text remains in Details and history, rendered as text, not HTML. Blank/missing work text explicitly says unavailable; a meaningful label is not fabricated full work text. Never open current task files to reconstruct a historical recording.

### Mechanical presentation copy, with semantic data intact

Copy the approved `style#monitor-visual-styles` content into `style.css` and its applicable HTML/class structure into React JSX. Replace conflicting old styles; do not layer another palette. Follow the existing README boundary: 14rem rail, compact run heading, full graph width when Details is closed, 18rem Details when selected, Close, responsive stacking and existing-style disclosures. Do not copy the proposal banner, `mockup-only-styles`, fixture coordinates/data, generated vendor blocks or fixture adapter. Production still imports ReactFlow and uses measured ELK layout. Production warning/evidence content is not synthetic sample text.

Keep graph semantic states separate from presentation classes in `graphFor`:

| Semantic evidence | Display color category | Node text requirement |
| --- | --- | --- |
| Planned/pending, no impediment | Not started (grey / `pending`) | Not started; preserve “run stopped” where known |
| Qualified recorded running | Running (blue / `running`) | Running with recorded-not-liveness qualification |
| Returned execution | Completed (green / `success`) | Returned; acceptance not established, or changes requested for rejected review |
| Failed or any other state, including waiting, blocked, interrupted, abandoned, unknown/incomplete or ambiguous | Failed (red / `failed`) | State's actual meaning/qualification, not an invented failure |

A completed checkpoint and a returned call remain separate facts. Do not make an unexecuted slot green from unrelated acceptance; do not recolor a returned worker because a check failed or a reviewer rejected. Keep progress, checkpoint proof, reviewer verdict/findings and full-range qualification distinct. A green rejected reviewer must still say **Returned · changes requested**. Four legend chips read exactly **Not started, Running, Failed, Completed**, with the compact explanatory note from the reference. Unsupported skipped/cancelled states are not synthesized; any exceptional state actually supplied uses red and truthful text.

Use one solid edge path style, including selected/focused edges. Keep `smoothstep`, actual endpoints, meaningful relation data/classification and selected edge Details. Do not prune attempts, review/fix nodes, stops, branches/joins or declared/recorded/mixed relations to simplify the picture. Existing invalid/missing/cyclic relation qualifications remain; one visual style does not make a declared prerequisite proof of execution.

Selection Details lead with short task title, role/state, full retained description where applicable, blocker, safe findings and material acceptance qualification. Metrics, checks and history can be collapsed, not deleted: keep This call / Task total / Overall run, session-context separation, coverage, unloaded counts, and paging controls. Real stale/read/unavailable warnings and material rejection/acceptance qualifications stay visible outside closed disclosures as needed. Neutral read timestamps may be collapsed. Removing duplicated chrome must not remove real warning information.
