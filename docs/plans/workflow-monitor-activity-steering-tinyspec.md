- Smooth, responsive graph dragging and panning; flat top-to-bottom DAG preserving actual branches and joins, without groups or planning nodes.

## Proposed behavior and implementation shape

### R1 — Actual activity and truthful edges

One node represents one actual task-worker, corrective-worker, fixer or reviewer invocation. Stable identity is run + invocation, not task label, role, timestamp, reused session or broad fixing-round ID. Retain meaningful separate attempts and failures; an SDK turn/tool/retry within that invocation is not a new graph call. Task contracts are descriptive context only. An empty run has no agent nodes. Missing plan presentation does not suppress actual calls. Review/fixer nodes are created from actual invocation start evidence, never planned review slots or configured limits.

Record minimal future facts in the existing recording mechanism: actual invocation identity/role/task association; exact input checkpoint and producer invocation references selected at task dispatch; correction trigger and predecessor invocation references when actually selected; first-review input membership and reviewed range; explicit failure/stop/support references. A checkpoint links its final producing invocation and retained earlier corrective chain, rather than choosing the latest occurrence in the viewer. Review membership names the known completed task outputs actually included by the runner, not every task in the plan or every commit in an arbitrary range. Unknown external-range contribution stays unknown. Distinct fixer corrective calls need their own invocation records and explicit linkage while retaining their fixing-round identity in Details.

These facts document **runner input/dispatch relationships**, not proof that a model read or obeyed prior work. Declared dependencies inform which completed inputs the runner selects; the recorded selection supplies the edge. Preserve all selected branches/joins, including multiple input checkpoints. The runner stays sequential; a branch denotes related inputs, not simultaneous execution. Ordinary recording remains optional observation: recording loss produces a visible gap/unknown relation, not a new workflow admission barrier.

Default arrows are restricted to:

- Recorded consumed task result: exact producing invocation → consuming invocation, with checkpoint reference in Details. No edges from plan entries, unstarted work or a Cartesian product of attempts.
- Recorded correction trigger/predecessor and actual review input: exact invocation endpoints. Multiple facts on one endpoint pair can share one arrow with all semantic facts retained in Details. Do not merge distinct calls.
- Recorded support → essential stopping failure, when both endpoints and relation have explicit evidence. A failure before any agent remains a stop node without an invented agent.

Routine checks/checkpoints, recovered errors, questions and successful internal work remain Details/history, not graph nodes. A failed agent is itself a failure node; do not add a duplicate non-agent failure unless a distinct unrecoverable internal operation explains the stop. Explicit terminal stopped-by evidence selects that operation; when its cause is missing, show the recorded terminal failure with **cause unknown**, not a guessed check or parent. A valid rejecting review can remain green for execution-return success with rejection clearly separate; it does not imply that a fixer ran.

Resolve relationships by exact recorded IDs and same-run identity (or an explicit exact cross-run reference if actually recorded). A run-level correction declaration alone cannot establish which fixer call was triggered; retain it as context, not a causal arrow. Invalid, missing, conflicting or cyclic relations remain qualified in Details/history. Render no invented repair, reversed edge, temporal chain or silently selected winner. Keep the DAG by excluding the invalid/cyclic relations from layout, disclosing their endpoints and reason. Existing chain metadata may alias a call only if the membership is unambiguous and denotes that same actual invocation; OI-16 shared membership must leave the occurrence visible as unassigned and retain its explicit stop support. Metadata alone must not create duplicate supposed calls.

Use a flat ELK layered DOWN graph of these validated edges and actual measured node dimensions. No owner rectangles, compound groups or plan anchors. Fit the initial view; preserve deliberate dragging/pan/zoom and selection across status-only refresh, without rerunning topology layout or undoing a drag. A true topology/content-size change may require layout but must not arbitrarily discard the user's viewport. Reject stale layout/fetch completions on navigation.

### R2 — Human-first Details within the disclosure boundary

Node title: concise recorded task/action plus useful task code, role and distinguishable attempt, not opaque IDs. Use already authorized `monitor.tasks` label/executive summary; generic/missing presentation falls back to action + task code/unknown, not private task prompt extraction. Details lead with task/action, recorded execution outcome, meaningful retained safe finding/result and stopping reason where available. Clearly say **unknown/not recorded** otherwise. Explain edge endpoints with human-readable actions and relation meaning; technical IDs come afterward.

Expandable references retain full available run/task/invocation/occurrence/execution IDs, source records, relation qualification, review range, check exit/category, checkpoint/no-change, findings and diagnostic history. Full-snapshot status/acceptance remains independent of paging; disclose unloaded history and preserve access to it. Do not lose a first rejection or failed corrective call when a later result succeeds. Green returned execution, accepted task work and full-range review acceptance remain different facts. Recorded running is not process-liveness proof; terminal/conflicting/incomplete and waiting facts remain honest.

Necessary small contract adjustment is **closed typed activity/input/stop provenance and safe phase/exit/error-category diagnostics**, propagated through recording validation, reader, mapper and DTO. It does not authorize exporting private `execution_history` prompts/errors, worker summary text, tool stdout, credentials, private local paths or transcripts. Existing authorized safe findings can be reused; reject accidental arbitrary payload forwarding, and do not treat a matching `path:line - finding` regex as authorization for private contents. No new descriptions generated by models, summarizers or reporting obligations. If useful prose is not already authorized, show available typed facts and unknown rather than expanding disclosure.

### R4 — Run identity, ordering, filtering and navigation

Derived minimal route: `/runs/id-<percent-encoded actual display_id>`. The fixed `id-` prefix prevents dot-only IDs from becoming browser path-navigation segments. Encode the entire actual ID as one URL component after that prefix; strip the prefix and decode exactly once, compare to the inventory's actual `display_id`, then use its opaque `ref` for existing API requests. IDs remain inert text. Reserved characters, Unicode, slash, percent and dot-only IDs must round-trip, not become filesystem paths or API refs.

At `/`, after a successful inventory read select the newest run and `replaceState` its run URL (no empty-root Back entry). If there are no runs, remain at `/` with an honest empty/unavailable state. Clicking a different run uses `pushState`; repeated selection does not add entries. `popstate` applies the URL selection without pushing again, clears obsolete Details/graph data and invalidates old requests/layout. Direct open and refresh serve the same bounded HTML shell, then resolve the exact ID. An unknown, removed or unavailable ID stays in the address bar and shows not-found/unavailable; never silently substitute another run. Transient read failure may retain clearly stale evidence only for the same selected ID, not another run.

Sort finite recorded `started_at` epoch seconds descending. Unknown/nonfinite timestamps go last; ties and unknown-time rows use deterministic actual-ID lexical ordering, not inferred ID chronology. Simple browser-side case-insensitive substring filtering matches actual run ID only. Filtering changes the list, not selection, URL, graph or history; show when the selected run is outside the filter and an explicit no-match state. Clearing restores sorted inventory. A poll inserting a newer run must not steal selection. Filter is local ephemeral UI state, not a new server search or persisted URL contract.

Server adds only the `/runs/…` HTML-shell boundary, serving its already inventoried index asset. Because routing frameworks decode encoded slash, validate the raw route/one encoded component and test the actual Starlette/HTTP boundary, not only a permissive fixture server. Malformed encoding/unsupported paths receive closed errors. Root, fixed assets and closed APIs keep Host, method, Fetch Metadata/header, CSP/no-store/nosniff protections. No public filesystem lookup or generic HTML fallback for unknown API/assets.

### R5 — Relay to exactly the active worker

Add the smallest parent tool to the existing project bridge, with a correlated message ID and explicit recipient **run/task/invocation/session** identity. The active runner advertises its current target privately to the authenticated bridge before accepting steering; session file paths/tokens are never public. The parent resolves the owner's intended current worker (e.g. C003) against that active identity and relays the message to it. A task ID alone cannot silently bind a later attempt. Fixer targets retain their actual task/round context. No-active, finished, mismatched or reviewer targets return a concrete unavailable/rejected result, not a queued successor message.

Use the existing authenticated private Unix bridge (run, parent session and token validation), a run-local adapter control connection and host stdin protocol. There is one decoder/dispatcher per stream; host request/reply messages need explicit correlation IDs so unsolicited control cannot steal a claim/command/cleanup/question response. Python control reception must remain serviceable while normal output handling waits on `ask_owner`; serialize writes and correlate callbacks without invoking the SDK concurrently from unrelated readers. No monitor endpoint, new daemon or persistent cross-task mailbox.

**Derived self-hosted delivery compatibility:** the running Python runner imports its adapter once, but each prompt starts a fresh host subprocess from disk. Therefore a host-only update must not require the new steering protocol from an already-running caller. Select multiplexed steering explicitly in the initial request; without that opt-in, preserve the current uncorrelated prompt/callback/reply protocol and emitted-record vocabulary, with no unsolicited target/steering status records. Existing `sessionObservations` remains an independent opt-in and is not steering consent. Only an adapter implementing the new contract opts in. Reuse this local capability pattern, not generalized version negotiation, historical-run compatibility/backfill or an automatic runner restart. A focused composed test of the original pre-change Python transport against the changed production host dispatcher must complete an ordinary prompt/callback exchange without new records before dependent adapter work; the opt-in path retains the real SDK queue/event proof.

The SDK host validates that the exact invocation/session is still active before `session.steer()`. Deliver an inert plain-text direction envelope carrying a unique message correlation ID, so repeated identical instructions can be distinguished and leading slash text is not treated as a skill/extension command. Preserve the instruction text; the envelope identifies it as owner direction within existing authority, not a new permission grant. Observe the actual SDK user `message_start` for that envelope before reporting consumption. Validate correlation against the installed input-processing behavior; queue-update/removal or `steer()` resolution alone never means delivered.

Expose status with identity and evidence:

- **accepted:** authenticated bridge accepted this exact recipient request; SDK queue not yet established.
- **queued:** host confirmed SDK queue insertion for that invocation; message has not yet been observed entering its conversation. It waits until the current assistant turn/tool calls finish; an unanswered `ask_owner` may delay it and must still receive its own correlated reply.
- **consumed / observed delivery:** matching SDK user-message event entered the target conversation. This proves delivery, **not obedience, acceptance of work, or permission to skip checks**.
- **failed / unavailable:** known rejection, queue failure, or known end of target before consumption. State the corrective action (inspect target/status and issue a new explicit request if appropriate), without restart or retargeting.
- **unknown:** connection/event loss prevents a trustworthy terminal acknowledgement. Do not relabel uncertainty as failure or success or resend automatically.

Tool returns the known immediate state; later correlated parent notification updates consumed/failed/unknown without blocking indefinitely for model compliance. Retain in-memory request correlation for this active invocation, including duplicate request handling, so reusing the same message ID does not enqueue twice; a deliberate new instruction uses a new ID. Message text stays in the authorized parent/worker conversation, not monitor DTOs or new SQLite prose records. Settlement, cancellation, EOF or session disposal closes the target and resolves outstanding statuses honestly. SDK retries/compaction are not new recipients; `agent_end` alone cannot close a still-active run. No mailbox survives to a later invocation, even if it reuses the same saved session. Reviewer unsolicited steering is excluded by the derived independent-review boundary; existing read-only review and owner-question behavior are preserved.

### R6 — Authority, delivery and operation

Future execution uses unchanged [.pi/workflow-executor.json](../../.pi/workflow-executor.json): Terra/medium workers and fresh Sol 6.1/medium reviewers for **every** new/continuation/corrective workflow launch. Astra planning is not implementation assignment. Separate tasks must be granular, independently verifiable Terra-sized outcomes, with concrete producer/consumer dependencies; this source is not that task list.

[ADR-0003](../decisions/ADR-0003-current-launch-authority-and-neutral-tasks.md) requires authorization-neutral task/check wording and current approved launch authority in initial/corrective prompts, while retaining actual scope/check/manual gates. [ADR-0004](../decisions/ADR-0004-shared-routine-worker-permissions.md) requires shared routine defaults, including small isolated tests/databases and ordinary scoped fixes without repeated approval. Neither authorizes unapproved implementation here, global installation, credentials, deployment, push, unrelated deletion or blind retry. Steering must not erase those defaults or expand them; task-owned paths, runner-owned focused checkpoints and independent read-only final review survive.

Changed extensions/tools require a **fresh Paseo-session handoff**, not `/reload` advice or automatic restart. The fresh agent verifies checkout/trust and loaded bridge tools before an approved launch. Never resume/relaunch historical runs for this feature. Build monitor assets **before** starting/restarting the monitor, or use a separate frozen asset copy; do not rebuild active hashes and assume the startup inventory can serve them. Restart only an authorized monitor preview, never a worker to preview UI changes.

Non-agent stop nodes show usage **not applicable**, not zero.
