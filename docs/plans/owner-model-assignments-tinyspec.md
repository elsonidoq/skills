## Approach and verified integration constraints

### One source per assignment domain

**Owner requirement:** create `skills/planner/references/model-assignments.json`, discovered relative to the installed planner skill, not the current project or a machine-specific checkout path. Existing skill-directory symlinks expose its references everywhere that installed planner is used. Do not copy planning bindings into project executor files or vice versa, and do not routinely ask owners to choose again.

**Technical choice:** use a small ordinary JSON representation and a concise shared contract consumed by existing stages. Represent current-session inheritance explicitly, including both model and effort, rather than treating absent values as inheritance. Reuse shared saved choices across the listed operations without independent hard-coded bindings, newly invented role aliases, schemas/services or profile registries. Exact serialization/key spelling is a mechanical implementation detail; the operation coverage and error semantics below are binding. All model-bearing planner-entry calls must resolve an explicit saved assignment before dispatch. Pass that assignment unchanged through direct calls, helper briefs/dispatch and fresh corrections; ambient agent settings must not override it. Changing a JSON binding must change every linked consumer without editing those consumers.

For corrections, retain the producing-stage assignment with the existing correction handoff/context, not a ledger. If the owner changes the file while old producing context is retained and the two disagree, identify the affected stage and ask the focused owner resolution; never silently run a different assignment or assume new content retroactively describes an old launch.

**Owner requirement:** both TinySpec and Standard task producers receive the selected executor config path **and read its actual JSON themselves before decomposition**. Derive executor model/effort for sizing and guidance from that file, never from the planning JSON, parent defaults or a remembered handoff value. Here [AGENTS.md](../../AGENTS.md) selects [`.pi/workflow-executor.json`](../../.pi/workflow-executor.json): workers/fixers are Terra/medium and reviewers/rereviewers Sol 6.1/medium. Reusable skills discover/pass the selected project's actual path, not a globally hard-coded `.pi` layout. Present/valid configuration requires no new model-selection question. Missing/ambiguous/invalid configuration asks only for necessary owner resolution, naming the affected role/path/problem. Reading configuration informs guidance but does not replace executor-sized, independently verifiable outcome decomposition.

Runner configuration remains separate and authoritative for execution. Remove `executor.get('reviewer', self.executor)`'s implicit reviewer assignment: absence is not owner authorization to share the worker binding. Explicit owner-configured sharing can use the same exact values, with independent review context preserved; never mutate current configured bindings merely to satisfy new validation.

### Exact dispatch and ordinary errors

Use ordinary SDK/runtime validation and available configuration facts at the relevant dispatch boundary, not authenticated readiness audits or paid probes. Missing, malformed, ambiguous, unsupported or unavailable exact assignment stops only the affected role/operation, naming the problem and requesting the smallest owner correction/selection; no candidate recommendation, fallback, silent default, model substitution, effort clamp, omitted effort or override. Ordinary safe tooling errors remain locally correctable within authority rather than becoming workflow admission ceremonies. A failed launch never authorizes model/effort changes. Inspect expensive failed runs and their actual invocations before targeted resume/retry; unknown failure remains a blocker, not a retry loop.

Requested configuration and exposed execution state are distinct. Report the requested binding and whatever actual model/effort the runtime exposes through existing session/return mechanisms; unknown actual stays unknown. An exposed mismatch must stop before prompting/work. Current-session parent configuration is intentional owner launch authority, not an inferred stage default. Do not fabricate provider-internal execution certainty from a session getter.
