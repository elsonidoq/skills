## Structured contract

Generate JSON matching the suite-delivered task.schema.json; no illustrative approvals are
usable authority. Include schema_version, origin/legacy_origin, original sources with hashes,
approval_refs, root execution_intent, authorization_envelope and tasks. Each task preserves
id/order/outcome/depends/context_group/owned_paths/required/optional/gates/envelope ID.
Each REQUIRED item retains criterion/check/version/args/pass_condition/expected_evidence/
producer_dependencies/gates. Inherit executor intent, not per-task model routing. Record
explicit compatible exact bindings and assessment provenance before execution; changed
intent assesses affected boundaries/detail/assumptions without whole-plan regeneration.
Luna/Terra/Sol scaffolding is qualitative owner guidance, never a universal ranking or a
reason to reduce acceptance or safety.

Ordinary approved-profile model tokens need no financial approval/cap/reservation. Separately
chargeable API/service actions need purpose/cost-impact explanation and explicit scoped owner
authority before effects. Missing capability/auth/containment remains a blocker. Preserve
original source/approval snapshots; inadequate historical contracts return to earliest
producing review/renewal, no mass conversion, forced Epic or STATE/history modification.

## Verification and approval

Validate explicit order/dependencies and human/machine parity. REQUIRED means required,
including source/owner/security/integration checks regardless of TDD preference. Static
validation does not prove runtime obedience. Record nonempty checks, exits and applicability;
planning-only final approval never starts implementation. Preserve actual hook/stage evidence.
Authorized retained task artifacts use the shared task-commit contract without bypassing
review/approval gates.
