# Illustrative risk selection walkthroughs — A, D, E

Offline expected planning examples only, not agent-produced plans or real-system experiments.
B/C producer/consumer task shapes are in risk-tiny-tasks.md and risk-standard-tasks.md.

## A — easy method name

Inspect the relevant version's source/documentation to resolve the name/type question.
No executable spike merely to print names/types. No numbered proof task: uncertainty is
answered by inspection, not a leverage-bearing semantic core. Evidence: inspected API span
and applicability. Gate: preparation authority only; no implementation performed.

## D — non-isolatable environment risk

Whole-environment failover is observable only with actual topology, credentials and fault
controls. Schedule real-system validation at the earliest feasible seam, not a forced
isolated script. Prerequisites: topology available, deployment fixture prepared, fault
controls and monitoring usable. Criterion: observed failover preserves acknowledged writes
and restores availability within source-defined bounds. Check: observed environment runner
and acknowledged-write/failover observables. Evidence: actual command/output, topology,
runtime/revision and limits. Gate: explicit environment/fault-operation permission and
available capabilities; unrun/unavailable REQUIRED validation remains NOT VERIFIED and
cannot release dependent production reliance. This example did not run a real-system check.

## E — disproof

Suppose adversarial proof output shows lost queued writes; expected zero loss fails.
Retain observed disproof, command, artifact, applicability and limits; failed technique
is not proven. Block the assumed T002 production approach, diagnose bounds and correct/replan
the affected downstream plan. Renew affected existing source/task reviews and approvals if
scope, acceptance or dependencies change. A corrected attempt retains the first failure;
no weaker criteria or blind retry. Missing capability is an evidence gap, not disproof.
Gate: no downstream release from failed/unrun proof; correction needs existing authority
and affected approval renewal. The hypothetical result is not an observed library failure.
